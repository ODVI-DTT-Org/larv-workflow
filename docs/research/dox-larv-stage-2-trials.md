# DOX larv Stage 2 Fresh-Agent Trials

Date: 2026-06-30
Related RFC: `docs/research/dox-larv-integration-rfc.md`

## Summary

Four fresh-context, read-only trial agents were run against the Level 1 DOX-inspired contract. All four scenarios passed the RFC Stage 2 threshold:

- Correct read chain identified without prompting: 4/4.
- Plausible freshness owner identified: 4/4.
- No scenario bypassed feature/debug/slice gates to start direct code edits: 4/4.
- No scenario indicated a full DOX tree was required.

Recommendation: keep Level 1. Do not add nested `AGENTS.md` files yet. The observed residual risk is moderate over-reading, not missed context.

## Trial Method

Each probe was run as an independent read-only fresh-session task with no chat context. The probe was asked to inspect repository-local generated templates, command docs, skills, and fixtures enough to report what it would read before edits and which local contract would own documentation freshness.

Pass criteria:

- Names the expected root entry points: starting file or `DOCS.md`, then `docs/Handsoff.md`.
- Identifies `STATE.yaml`, tracker, and the nearest owning contract for the workflow.
- Identifies a plausible doc freshness owner after meaningful changes.
- Does not start direct app code edits before workflow gates.

## Scenario Details

### Greenfield Handoff

Read chain identified:

1. `.codex/AGENTS.md` or equivalent generated starting-point file
2. `DOCS.md`
3. `docs/Handsoff.md`
4. `docs/larv/STATE.yaml`
5. `docs/larv/implementation-tracker.yaml`
6. latest `docs/larv/08-implementation/reports/`, if any
7. `docs/larv/07-runtime/sandbox-url.txt`, if present
8. `docs/user-manual/README.md`
9. `docs/user-manual/seed-data.md`
10. `docs/Handsoff/bootstrap-sandbox.md`
11. first incomplete `docs/Handsoff/slice-NN-<name>.md`
12. supporting domain/design/test docs named by the slice

Nearest contract: active `docs/Handsoff/slice-NN-<name>.md` for app code.

Freshness owner: slice handoff/report, user testing guide, seed-data guide, tracker, `STATE.yaml`, and local learnings as applicable.

Residual risk: moderate over-read risk if an agent scans broad `docs/larv/` history instead of following the route table.

### Adopt/Resume

Read chain identified:

1. `DOCS.md`
2. `docs/Handsoff.md`
3. `docs/larv/STATE.yaml`
4. `docs/larv/implementation-tracker.yaml` and latest implementation reports
5. adoption report
6. route map or route evidence, if generated by adoption
7. confidence-marked domain/architecture/test docs
8. active slice or feature/debug slice handoff

Nearest contract: active slice handoff for `routes/` work, with adoption evidence and confidence-marked docs as required context.

Freshness owner: adoption report if confidence changes; otherwise relevant larv docs plus tracker/state/report as required by the active slice.

Residual risk: the probe expected a route-map artifact that is not proven by current fixtures. This suggests adoption docs should either standardize such a path later or avoid implying it.

Freshness owner: feature docs, tracker, `STATE.yaml`, regenerated handoff/start files, `DOCS.md`, user manual, seed-data guide, and local learnings as appropriate.

Residual risk: moderate over-read risk because root starting files, `DOCS.md`, `Handsoff`, feature docs, and slice handoffs stack up.

8. generated app `docs/larv/implementation-tracker.yaml`
9. `docs/larv/05-premortem/debug-<issue-slug>-rca.md`
10. `docs/Handsoff/slice-NN-<bug-slice>.md`
11. any domain/design/test docs named by that slice

RCA/regression chain identified:

- `docs/larv/05-premortem/debug-<issue-slug>-rca.md`
- bug slice appended to `docs/larv/06-implementation/elephant-carpaccio.md`
- active bug slice at `docs/Handsoff/slice-NN-<name>.md`
- regression test requirement in slice DoD

Nearest contract: debug RCA plus active bug slice handoff; for source edits, the active debug slice handoff controls app paths.

Freshness owner: active slice handoff/report chain, tracker, `STATE.yaml`, relevant user manual docs, seed-data guide if affected, local learnings, and starting-point freshness via handoff regeneration.

Residual risk: moderate-low over-read risk due to overlap among `DOCS.md`, `Handsoff`, generated starting files, RCA, tracker, state, and slice docs.

## Decision

Stage 2 passes. Keep the Level 1 contract in existing generated starting-point files and do not add nested `AGENTS.md` files in this iteration.

Next useful follow-up:

- tighten adoption artifact naming if larv intends to generate a route map for adopted apps
- optionally add a small test or fixture for adopted-app guidance once adoption output paths are standardized
- keep monitoring real workflow failures for missed path-local context before considering Level 2

## Follow-Up Override

After review, the user chose to trial a nested DOX tree in one real project, likely DTT Dashboard. The implementation should therefore generate nested contracts with guardrails:

- always generate `docs/larv/AGENTS.md` and `docs/Handsoff/AGENTS.md`
- generate `app/AGENTS.md`, `resources/AGENTS.md`, and `tests/AGENTS.md` only when those directories already exist, so docs-only greenfield scaffolding is not polluted before Laravel is installed
- keep nested files concise and referential, routing to active slice, feature, debug, verification, deploy, design, and test contracts instead of duplicating them
- keep observing real workflow behavior before adding deeper nested contracts
